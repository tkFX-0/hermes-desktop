# Cursor Agent Escalation

## 1. 位置づけ

Cursor Agent / Cursor SDK / GPT-5.5などの高性能AIは、Hermesの代替ではなく、外部高性能エージェント連携として扱う。

役割分担:

- Hermesは、ローカルSandbox内の開発ループ担当である。
- Cursor Agentは、難所突破、高度レビュー、複雑修正の専門医である。
- イツキシマは、審査、説明、承認整理を担当する。
- ユーザーは、目的、リスク、最終承認を判断する。

基本方針:

```text
Hermesはローカルで試す。
Cursor Agentは難所で使う。
イツキシマは境界と説明を守る。
ユーザーは最終判断を行う。
```

Cursor Agentの提案は、そのまま採用しない。必ずイツキシマ審査とユーザー向け変更レポートを通す。

## 2. エスカレーション条件

次のいずれかを満たす場合、Cursor Agentへ渡す候補とする。

- Hermesが2回以上失敗した。
- 根本原因が不明。
- アーキテクチャ変更が絡む。
- セキュリティが絡む。
- EA/MT5まわりで誤りが損失につながる。
- 非同期処理や依存関係が複雑。
- 差分が大きい。
- ローカルLLMの回答に不安が残る。
- ユーザーが明示的に高性能AIレビューを希望した。

エスカレーションは「便利だから使う」ではなく、「ローカルHermesだけでは判断または実装の信頼性が不足する」場合に使う。

## 3. 渡してよい情報

Cursor Agentへ渡してよい情報は、目的達成に必要な最小限に限定する。

- 関連する設計文書。
- 抽象化されたエラー内容。
- 関連コードの必要最小限の抜粋。
- テスト結果。
- Hermesの失敗ログ。
- 変更対象ファイルの要約。

渡す前に、秘密情報、個人情報、取引情報、記憶情報が混ざっていないか確認する。

## 4. 渡してはいけない情報

次の情報はCursor Agentへ渡してはいけない。

- `.env`
- APIキー。
- secrets。
- memory DB。
- 個人情報。
- 取引履歴。
- MT5口座情報。
- ブラウザCookie。
- SSHキー。
- クラウド認証情報。
- 本番設定。
- ユーザーの長期記憶そのもの。

これらが関係する場合は、内容そのものではなく、抽象化した説明だけを渡す。

## 5. 出力形式

Cursor Agentの結果もHermesと同様に、イツキシマ審査用の変更レポート形式へ変換する。

自由文だけで採用してはいけない。

最低限含める情報:

- 何を提案しているか。
- なぜ必要か。
- どのファイルや機能に影響するか。
- 触ってはいけない領域に触れていないか。
- 実行済みテストと未確認項目。
- リスク。
- 戻し方。
- イツキシマの判定。
- ユーザーに求める判断。

不明な点は空欄にせず、未確認項目として扱う。

## 6. 承認フロー

Cursor Agent連携時の流れ:

```text
Cursor Agentが提案する
  ↓
イツキシマが危険度、目的ズレ、秘密情報混入、差分影響を審査する
  ↓
ユーザーが最終承認する
  ↓
本体反映前に変更レポートを出す
  ↓
承認後の専用反映ステップで適用する
```

Cursor Agentは承認者ではない。イツキシマも承認を代行しない。最終承認はユーザーが行う。

本体反映前には、必ず変更レポートを出す。

## 7. 課金・コスト方針

Cursor Agent / SDK / GPT-5.5などの高性能AIは常用しない。難所突破用として使う。

方針:

- ローカルHermesで済むものはローカルで処理する。
- Cursor Agent使用時は、作業目的と期待成果を明確化する。
- 無制限に投げない。
- 同じ不明点を繰り返し投げず、Hermesの失敗ログと未確認項目を整理してから渡す。
- 高リスク領域が絡む場合は、渡す前にユーザーへ目的と範囲を説明する。

コストをかける理由が説明できない場合は、まずローカルで整理する。

## 8. 今回の扱い

今回は要件定義のみとする。

実施しないこと:

- 実装しない。
- SDK接続しない。
- 外部通信しない。
- Cursor Agentへ実際に送信しない。
- 既存EA本体やMT5関連には触れない。
- `.env`、APIキー、secrets、memory DB、本番設定、取引履歴、個人情報には触れない。

この文書は、将来Cursor Agent / Cursor SDKを連携する場合の安全条件と承認フローを定義するための準備資料である。

## 9. Local / Cloud Policyとの関係

ローカルLLM、Hermes、Cursor Agent、GPT/Claude系モデルの使い分けは `LOCAL_CLOUD_ESCALATION_POLICY.md` に分離する。

この文書はCursor Agent固有の扱いを定義し、`LOCAL_CLOUD_ESCALATION_POLICY.md` はローカル/クラウド全体の判断基準を定義する。
