# Implementation Plan

## 1. 設計上の矛盾と危険な前提

### 1.1 「自律」と「寄り添い」の衝突

Hermesは自律的に動くほど価値が出る。一方、イツキシマは沈黙と距離感が価値になる。

対策:

- Hermesの自律性はSandbox内に限定する。
- イツキシマは発話と境界越えを審査する。
- イツキシマ自身には開発ループを持たせない。

### 1.2 「記憶」と「安全」の衝突

記憶が増えるほど文脈理解は強くなるが、誤記憶、過剰記憶、センシティブ情報の保持リスクが増える。

対策:

- 長期記憶は承認制。
- 安全ポリシーはAIが自動更新しない。
- 記憶には失効時刻と信頼度を持たせる。

### 1.3 「ローカル」と「安全」の混同

ローカル実行でも、`.env`、記憶DB、MT5、取引履歴、ブラウザCookieは危険領域である。

対策:

- パスガードを最初に実装する。
- 外部通信を既定OFFにする。
- MT5/EA関連を既定拒否する。

### 1.4 「承認」と「承認疲れ」

承認を増やすと安全に見えるが、承認疲れにより実質的に確認されなくなる。

対策:

- Sandbox内は承認不要。
- 本体反映、高リスク操作、外部送信だけ承認。
- 承認レポートを非エンジニア向けにする。

### 1.5 「可視化」と「演出」

可視化が実データと離れると、信頼できない雰囲気UIになる。

対策:

- 状態JSONを先に作る。
- 実状態と演出を必ず紐づける。
- 何もしていない時は静止または待機表示にする。

## 3. 実装順序

### Phase 0: 文書と境界

- 設計ドキュメントを固定する。
- 禁止領域を定義する。
- Sandbox rootを決める。
- 承認レポート形式を固定する。

完了条件:

- 禁止領域の一覧がある。
- Sandbox外へ出る条件が説明できる。
- ユーザー向け変更レポートのテンプレートがある。

### Phase 1: Hermes Autonomy Zone

- `sandbox/hermes-autonomy-zone/` を作る。
- Zone内だけ書けるFile APIを作る。
- 禁止パスを拒否する。
- 外部通信をOFFにする。
- 変更案をapproval queueへ出す。

完了条件:

- Zone内ファイル作成ができる。
- Zone外書き込みが拒否される。
- `.env`、MT5、memory DBが拒否される。

### Phase 2: 変更レポートと承認キュー

- Hermes出力JSONを受け取る。
- イツキシマが変更レポートへ変換する。
- 承認、保留、修正、破棄を記録する。

完了条件:

- コードを読まずに判断できるレポートが出る。
- 未確認テストが明示される。
- 戻し方が書かれる。

### Phase 3: イツキシマ沈黙ゲート

- Observe/Recall/Judge/Silent/Speak/Waitを実装する。
- 介入価値スコアを作る。
- 通知頻度を短期記憶で調整する。

完了条件:

- 発話候補が作られても沈黙できる。
- 同じ通知を短期間で繰り返さない。
- 緊急度と集中中フラグを考慮する。

### Phase 4: 記憶

- 一時記憶と作業記憶を実装する。
- 長期記憶候補は承認キューに送る。
- 失効と削除を実装する。

完了条件:

- 長期プロフィールを勝手に更新しない。
- 安全ポリシーを勝手に更新しない。
- 誤記憶候補を保留できる。

### Phase 5: 可視化

- 状態JSONを出す。
- Dev Modeを作る。
- Ambient Modeを実データに接続する。

完了条件:

- 実際の状態と表示が一致する。
- 承認待ちとリスクが見える。
- 動いていない時に動いているように見せない。

## 4. 最初のMVP

最初のMVPは小さくする。

含める:

- 設計ドキュメント。
- Sandbox root。
- 禁止パスガード。
- Hermes出力JSONの受け取り。
- 変更レポート生成。
- 手動承認キュー。
- イツキシマの沈黙ゲートのルール実装。

含めない:

- memory DB直接編集。
- MT5連携。
- 外部通知。
- 自動本体反映。
- OpenClaw連携。
- 完全な3D可視化。

## 5. 寄り添いループ

```text
Observe
  現在状況を軽く見る

Recall
  短期記憶・作業記憶・プロジェクト記憶と照合

Judge
  介入価値、緊急度、集中破壊コスト、安全性を評価

Silent
  価値が足りなければ黙る

Speak
  価値が高い時だけ短く話す

Wait
  ユーザー反応を待つ

Adjust
  通知頻度と距離感を短期的に調整する
```

## 6. 未解決論点

- Sandboxを単一ディレクトリで始めるか、Docker等のプロセス隔離まで最初から入れるか。
- イツキシマの状態観察をどこまで許可するか。
- 通知先をローカルUIだけにするか、将来Discord/Telegramへ広げるか。
- 長期記憶の保存形式をMarkdown、SQLite、JSONLのどれにするか。
- Hermes既存のmemory/tool approvalとイツキシマ側ポリシーをどう統合するか。

初期判断:

- 最初は単一ディレクトリSandboxで始める。
- 外部通知は入れない。
- 長期記憶は自動保存しない。
- MT5/EAは完全隔離する。
