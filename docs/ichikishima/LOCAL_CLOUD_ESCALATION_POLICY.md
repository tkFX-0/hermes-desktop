# Local / Cloud Escalation Policy

## 1. 目的

12GB VRAMローカル環境と、GPT / Claude / Cursorなどのクラウドまたは高性能AIを安全に使い分ける。

この文書は外部通信実装ではない。実際の送信、SDK接続、外部API利用はまだ行わない。

## 2. ローカルでやること

- 軽作業。
- 文書整理。
- テスト案。
- 小修正。
- Shadow Mode判定。
- Hermes sandbox作業。
- 変更レポート整理。
- approval request candidate作成。

## 3. クラウドへ渡す条件

- Hermesが2回失敗した。
- 原因不明。
- セキュリティ境界に関わる。
- EA/MT5関連。
- 損失に直結する変更。
- 大きな設計変更。
- 非同期/依存関係が複雑。
- ローカル回答に不安が残る。

## 4. 渡してよい情報

- 最小限のコード抜粋。
- エラー要約。
- テスト結果。
- 設計文書。
- 抽象化したログ。
- 変更レポート。

## 5. 渡してはいけない情報

- `.env`
- APIキー。
- secrets。
- memory DB。
- 個人情報。
- 取引履歴。
- MT5口座情報。
- 長期記憶の生データ。
- ブラウザCookie。
- SSHキー。
- クラウド認証情報。

## 6. モード制

- Sleep: 重い推論を停止。
- Watch: 軽量監視のみ。
- Companion: 短文応答とShadow Mode判定。
- Dev: Hermes sandbox作業。
- Research: 設計比較と文書化。
- High Risk Review: 高性能AIレビュー候補を作る。

## 7. エスカレーション前チェック

- 渡す情報に秘密情報がない。
- 目的が明確。
- 期待する判断が明確。
- テスト結果が整理されている。
- ユーザー承認が必要な高リスク領域では、送信前に確認する。

## 8. 初期実装方針

初期実装では、エスカレーション候補の文書化とReview Modeでの判定候補までに留める。

外部送信やSDK接続は別Goalで扱う。
