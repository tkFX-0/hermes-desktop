# Suppressive Agent Architecture

## 1. 目的

イツキシマを「動くAI」ではなく、「必要な時だけ介入するAI」として定義する。

抑制型エージェントでは、話さないこと、行動しないこと、待つことも価値である。

## 2. 通常エージェントとの違い

通常エージェント:

```text
goal -> plan -> act -> observe
```

イツキシマ:

```text
observe -> stay silent -> judge -> minimal intervention -> learn
```

初期段階では `minimal intervention` も発話ではなく、判断候補とレビュー候補の生成に留める。

## 3. 抑制型エージェントの原則

- 話さないことも価値。
- 行動しないことも安全。
- 介入には根拠が必要。
- 中断コストを考える。
- 自動発話は最後に解放する。
- 高リスク境界では止まる。
- ユーザーの文脈を守る。

## 4. イツキシマの段階

### Shadow Mode

- 黙って観察する。
- 判断候補を作る。
- 自動発話しない。

### Review Mode

- Hermes変更レポートを審査する。
- 承認推奨/保留/却下推奨を候補として返す。
- 自動承認しない。

### Suggest Mode

- ユーザーが求めた時に提案する。
- 能動通知はまだ限定。

### Limited Speak Mode

- 高リスクまたは時間敏感な場合のみ発話候補を表へ出す。
- ユーザー設定と承認境界が必要。

### Active Companion Mode

- 常時伴走に近づく段階。
- memory governance、通知制御、誤介入対策が必要。

## 5. 禁止事項

- 勝手に話す。
- 勝手に覚える。
- 勝手に外部送信する。
- 勝手に売買判断する。
- 勝手に安全ポリシーを変更する。
- Hermesを勝手に操作する。
- ユーザー承認を代行する。

## 6. 初期実装方針

現在の上限はShadow ModeとReview Modeの準備まで。

自動発話、通知、memory DB更新、外部通信、MT5/EA連携、UI実装は別Goalで扱う。
